# Хостинг в Yandex Cloud

## Зачем

Российские мобильные операторы режут соединения с Vercel после первых
~16 КБ: на телефоне без VPN сайт приходит без стилей и скриптов.
Поэтому сайт переезжает на российский хостинг — Yandex Object Storage.

## Сколько стоит

При нынешнем масштабе всё укладывается в бесплатные лимиты Yandex Cloud,
то есть **0 ₽ в месяц**:

| Что | Бесплатно каждый месяц | У нас |
| --- | --- | --- |
| Хранение в Object Storage | 1 ГБ | ~46 МБ |
| Запросы GET к сайту | 100 000 | ~15 на просмотр страницы → ~6 000 просмотров |
| Исходящий трафик | 100 ГБ | |
| Вызовы функции (форма) | 1 000 000 | по одному на заявку |
| Сертификат Let's Encrypt | бесплатно | |

Сверх лимита — копейки (например, 10 000 запросов GET стоят меньше рубля).
Без привязанной карты Yandex Cloud не даёт пользоваться даже бесплатными
лимитами. Платный Cloud DNS мы не используем: DNS остаётся у регистратора.

## Как всё устроено

- **www.grabyou.ru** — сайт, отдаётся из бакета Object Storage.
- **grabyou.ru** — остаётся на Vercel и просто перенаправляет на www.
  Ответ-перенаправление крошечный и проходит даже сквозь порезанное соединение.
- **Форма «Партнёрам»** — Yandex Cloud Function, код лежит
  в `partner-function/index.js`, заявки уходят в тот же Telegram.
- **Деплой** — как и раньше, на `git push` в `main`: GitHub Actions собирает
  сайт и выкладывает его в бакет (`.github/workflows/deploy-yandex.yml`).
  Пока ключи в GitHub не заданы, workflow просто пропускается.

## Настройка — один раз

### 1. Аккаунт

1. Зайдите на [console.yandex.cloud](https://console.yandex.cloud) с Яндекс ID.
2. Создайте платёжный аккаунт и привяжите карту. Новым аккаунтам дают
   стартовый грант. При нашей нагрузке списаний не будет.

### 2. Бакет для сайта

1. **Object Storage → Создать бакет**:
   - имя — ровно `www.grabyou.ru` (оно должно совпадать с доменом);
   - доступ на чтение объектов — **публичный**;
   - класс хранилища — стандартное.
2. Бакет → **Веб-сайт** → **Хостинг**:
   - главная страница — `index.html`;
   - страница ошибки — `404.html`.

### 3. Ключ для GitHub

1. **Identity and Access Management → Сервисные аккаунты → Создать**:
   имя `grabyou-deploy`, роль `storage.editor`.
2. Откройте аккаунт → **Создать новый ключ → Статический ключ доступа**.
   Сохраните идентификатор и секрет — секрет показывается один раз.
3. GitHub → репозиторий → **Settings → Secrets and variables → Actions →
   Secrets → New repository secret**:
   - `YC_S3_KEY_ID` — идентификатор ключа;
   - `YC_S3_SECRET` — секретный ключ.

### 4. Функция для формы

1. **Cloud Functions → Создать функцию**, имя `grabyou-partner`.
2. Включите **Публичная функция**.
3. **Редактор**: среда Node.js 22 (подойдёт и 20), способ — редактор кода.
   Создайте файл `index.js` и вставьте в него содержимое
   `deploy/yandex/partner-function/index.js`.
   - Точка входа: `index.handler`
   - Таймаут: 10 секунд, память: 128 МБ
   - Переменные окружения: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` —
     те же значения, что сейчас в Vercel (Settings → Environment Variables).
     Если Vercel их не показывает, токен можно заново получить у @BotFather.
4. **Сохранить изменения**. Скопируйте ссылку функции — она вида
   `https://functions.yandexcloud.net/d4e...`.
5. GitHub → **Settings → Secrets and variables → Actions → Variables →
   New repository variable**: `PARTNER_API_URL` = эта ссылка.

### 5. Первая выкладка

GitHub → **Actions → «Деплой в Yandex Cloud» → Run workflow**.
Через 2–3 минуты сайт откроется по техническому адресу:
<http://www.grabyou.ru.website.yandexcloud.net>
(только по http — сертификат появится на шаге 6).

### 6. HTTPS-сертификат

1. **Certificate Manager → Добавить сертификат → Сертификат от Let's Encrypt**,
   домен `www.grabyou.ru`, тип проверки — **DNS**.
2. Консоль покажет запись для проверки: CNAME `_acme-challenge.www.grabyou.ru`.
   Добавьте её у регистратора домена.
3. Дождитесь статуса **Issued** (обычно до 30 минут).
4. Бакет `www.grabyou.ru` → **HTTPS** → источник **Certificate Manager** →
   выберите этот сертификат.

### 7. Переключение домена

У регистратора домена (там, где сейчас DNS-записи grabyou.ru):

| Имя | Тип | Значение |
| --- | --- | --- |
| `www` | CNAME | `www.grabyou.ru.website.yandexcloud.net.` |

Старую запись для `www`, которая ведёт на Vercel, удалите. Корень `grabyou.ru`
не трогайте — он продолжает смотреть на Vercel.

В Vercel → проект → **Settings → Domains**:
- у `grabyou.ru` включите **Redirect to** `www.grabyou.ru`;
- домен `www.grabyou.ru` из проекта удалите.

### 8. Проверка

С телефона **без VPN**, через мобильный интернет:
1. Откройте <https://www.grabyou.ru> — сайт должен прийти со стилями.
2. Откройте <https://grabyou.ru> — должно перенаправить на www.
3. Отправьте тестовую заявку на странице «Партнёрам» — она должна прийти
   в Telegram.

## Если что-то не так

- **Workflow падает на выкладке с `AccessDenied`** — у сервисного аккаунта
  нет роли `storage.editor`, или в секретах перепутаны идентификатор и секрет.
- **Сайт открывается, но `/partners` отдаёт 404** — проверьте, что последний
  запуск workflow прошёл целиком: копии страниц без `/` на конце
  выкладываются отдельным шагом.
- **Форма пишет «Не получилось отправить»** — проверьте, что задана переменная
  `PARTNER_API_URL`, после этого сайт пересобран, а функция публичная.
  Если сайт открыт не с `www.grabyou.ru` и не с `grabyou.ru`, добавьте адрес
  в переменную функции `ALLOWED_ORIGINS` (через запятую).
- **grabyou.ru без www всё равно не открывается** на каком-то операторе —
  значит, там режут Vercel целиком, а не только после 16 КБ. Тогда
  основным адресом делайте www и давайте ссылки на него.
